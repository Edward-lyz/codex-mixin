# macOS「模型与服务」统一工作台计划

日期：2026-09-10。状态：P0 + P1 已实现，等待 macOS build 与人工实测；P2 未实现。

## 结论与范围

建议把「供应商设置」和「模型选择与测速」合并成一个「模型与服务」窗口：左侧选择服务商，右侧默认展示模型，连接配置在当前服务商内展开。统一选中对象、状态解释、草稿与应用反馈，让用户在同一处完成接入、选模型、验证速度和处理异常。

用户的主要任务是「让某个模型在 Codex 中可用」，以这个结果组织页面。普通文案使用「服务商」，Provider ID、协议和错误码留在详细信息。Fusion 继续使用现有独立入口；额度、Token 统计沿用现有展示，避免扩大本期范围。

最小交付是 P0 + P1。P2 的「先测再加入」单独评估，不阻塞统一窗口上线。

## 当前实现与问题依据

本计划通过 `rtk git status --short`、`rtk proxy rg -n ...`、`rtk proxy sed -n ...` 静态阅读 macOS 界面、CLI JSON、readiness 与 benchmark 调用链得出。未读取用户密钥，未调用在线模型，未启动或修改运行中的配置。以下是源码事实，UX 收益仍需用户任务验证。

| 发现 | 影响 | 代码位置 |
| --- | --- | --- |
| 菜单有两个入口、两个 window controller，两个 model 各自加载 providers 和维护 selectedProviderID | 用户在设置后需要重新找到同一服务商，刷新结果与草稿也没有统一管理 | `macos/MenuBarApp.swift:127`、`macos/SettingsActions.swift:58`、`macos/ModelBenchmarkWindow.swift:26` |

| readiness 从配置和模型缓存计算，没有在这里执行真实推理 | `healthy` 只能支持「配置就绪」；`model_refresh_failed` 也不等于所有模型不能推理 | `src/provider/types.rs:382` |

| 选择服务商会重填连接表单；模型列表重新加载会重置 selected/saved 集合 | 合并时需要保护草稿，不能让刷新和切换覆盖编辑 | `macos/ProviderSettingsView.swift:49`、`macos/ModelBenchmarkWindow.swift:347` |

## 目标页面

- 菜单只保留「模型与服务…」。菜单上的异常摘要可点击，定位到对应服务商和问题区。
- 左侧：官方账号（保持现有只读连接行为）、各服务商、添加服务商。每行显示名称和具体状态，如「已加入 3 个 · 列表更新失败」。保留排序与停用能力。首版不引入跨服务商汇总编辑。
- 右侧顶部：服务商名称、已加入模型数、配置状态、最近模型列表更新时间，以及「连接设置」展开入口。有问题时显示持久的问题提示与处理按钮。
- 右侧主体：模型搜索、全部/已加入/新增/需要处理筛选，模型列表和测速结果。默认只显示「加入 Codex、模型、状态、首字延迟、生成速度」；上下文与能力放行详情或可选列，倍率沿用原语义，不能直接解释成价格。
- 右侧底部：当前服务商的改动摘要与一个「应用更改」主按钮；不混入其他服务商草稿。没有改动时显示当前应用状态。
- 「更多」包含手动模型、完整测速、能力检查、高级连接字段。模型列表始终是主工作区。

连接设置使用当前 detail 区内的原生 DisclosureGroup/Form，用户无需离开当前服务商。必需的地址与凭据优先展示；AWS 凭据、额度认证、绘图路径、辅助模型路由、Baidu bridge 等沿用原条件和字段语义。辅助模型不可用与普通模型异常分别呈现。

默认窗口约 1100 × 720，适配 13 寸屏幕；侧栏可收起，窄窗口隐藏可选列或展开行详情。保留键盘搜索、空格勾选和 Cmd+S；VoiceOver 能读出服务商、模型、问题和处理动作。状态有文字，不仅靠颜色；核心原因和按钮不能依赖 hover。

## 状态文案与处理动作

内部 readiness enum 保留，macOS 根据结构化事实生成展示状态。主文案不再显示「Provider 降级」。一个服务商可同时有多个问题：优先展示阻塞问题，其余展开查看；停用的服务商不计入当前使用告警。

| 判断条件 | 主文案与影响说明 | 动作 |
| --- | --- | --- |
| 已停用 | 已停用；该服务商的自定义模型不会承接请求 | 启用 |
| 凭据缺失 | 尚未配置密钥；该服务商暂不能使用 | 填写密钥，展开并聚焦对应字段 |
| selected=0、cached>0、未停用 | 还没有加入模型；从下方选择后应用 | 选择模型，聚焦模型列表 |
| cached=0，尚未成功刷新且无有效手动模型 | 尚未获取模型列表 | 获取模型列表；支持时提供手动添加 |
| 部分已选模型不在缓存，其他仍可路由 | 2 个已选模型不在当前列表；其余 3 个配置就绪 | 查看受影响模型；重新获取列表；移除指定选择 |
| 刷新失败，仍有缓存中可路由的模型 | 模型列表更新失败；显示上次成功获取的列表（时间） | 重试更新；错误详情 |
| 已选模型全部不可路由 | 当前已选模型暂不可用；列出具体原因 | 更新列表或重新选择 |
| 配置与缓存无问题 | 已加入 N 个模型 · 配置就绪 | 可主动运行实际模型测试 |
| 实际模型测试返回失败 | 此模型测试失败：超时/鉴权失败/上游错误及时间 | 重试此模型；鉴权失败时打开连接设置 |
| 仅额度查询失败 | 额度暂时无法查询 | 更新额度凭据；不据此宣称推理不可用 |

鉴权失效只能依据实际响应判定，不能从「凭据已保存」推断有效性。仅缓存缺项不能宣称上游永久下架。刷新失败的确切原因来自原始错误；没有结构化 HTTP 分类时先显示经过脱敏的详情，不靠关键词猜测。

总状态拆成「本地服务运行中」与「1 个服务商需要处理」。问题影响范围以服务商/模型计数说明；保留官方账号和自定义服务各自的边界。轻量 health 检查发现 readiness 变化时补拉一次结构化详情，不能长期使用旧的异常说明。

## 关键操作闭环

### 添加服务商

1. 当前窗口打开添加 sheet：选择预设，填写必要参数。
2. 明确显示实际阶段：保存服务商、获取模型、应用到本地服务与客户端目录。
3. 成功后直接选中新服务商，展示模型列表及当前已加入数量，不需要再开测速窗口。
4. 首版保留当前首次默认选择至多 10 个模型的行为，但必须告诉用户「已按现有规则加入 N 个，可以调整」。列表顺序不表示质量推荐。
5. 若配置已保存而发现模型失败，显示「服务商已保存，获取模型失败」并留在该对象；重试发现，不重复添加。能手动指定模型的情况保留入口。

### 编辑与应用

- 基于每个 provider ID 保存草稿；切换服务商和展开配置不丢输入。配置编辑、模型选择和手动模型上下文构成当前服务商的改动集。
- 按钮写「应用更改」，摘要写清「连接设置已修改；加入 2 个，移除 1 个」。应用前静态校验、校验 Fusion/辅助模型引用等现有约束。
- 顺序为写入连接变更、写入模型选择、重启需要更新的网关、刷新受影响的已安装客户端目录、重新读取结果。同一次应用在 macOS 编排层只触发一次网关重启；必须审计 CLI 已有 after-commit 同步，避免再次重复刷新。
- 这不是原子事务：已有命令可能先写配置再在发现/同步阶段失败。记录成功阶段并及时显示「配置已保存，模型目录更新失败」等结果；重试从失败阶段继续，不重复已经成功的副作用。
- 官方模型选择沿用已有专用路径。官方连接不可编辑，不能当成普通 API Key 服务商。
- 状态刷新更新已保存快照，不覆盖本地草稿；若外部 CLI 修改了当前编辑对象的同一字段，提示冲突并让用户重新核对，不静默覆盖。比较相关字段即可，不把 config_version 的 schema 版本当成配置修订号。
- 关闭有草稿的窗口时提供保存/放弃/继续编辑；退出时清理内存中的未保存密钥。成功后显示一次内联结果，不叠加成功弹窗；需要重启 Codex 时明确提示，不能宣称运行中的 Codex 已读到新列表。

### 刷新模型

首版沿用现有发现规则，操作前在可见帮助中说明可能同步调整已加入列表，完成后展示「新增 A、移除 B、自动加入 C」及具体模型。存在草稿时禁止刷新，并给出「先应用或放弃当前更改」动作，不用无解释的灰色按钮。

目标版本可改成「刷新仅发现；新增模型由用户确认加入」，这是行为变更，需单独更改 discovery 的策略并更新 CLI/TUI 约定与测试，不能在 UI 合并时悄悄引入。

### 测试与测速

- 把现有测试连接按实际模式命名为「检查模型接口」或「检查静态配置」，成功消息标明检查范围。
- 常用测速叫「测试响应速度」，默认测首字延迟；完整模式展示首字延迟和生成速度。显示测试模型数、范围、超时与时间。付费推理说明放在操作旁，不另外增加每次确认弹窗。
- 首版测试当前服务商已经应用的模型，主按钮明确写「测试已加入的 N 个模型」。搜索只是过滤显示，不偷偷缩小范围。单行重测使用已有 models filter，传入正确的 catalog slug。
- 有草稿时显示「先应用更改，再测试」和相邻的应用按钮。测试本身不隐式保存、不更改选中模型。
- 失败只标记对应模型及本次测试时间。未测、超时、失败和旧结果分别呈现；快速测速不能让旧 TPS 看成同一轮测量结果。
- 禁止用一次测速自动挑选模型、自动切换服务商或推断质量；保留用户显式选择。
- 在运行中显示可返回其他服务商浏览的进度。对会重启网关的变更进行串行互斥；未实现后端取消前不展示虚假的「取消」按钮。关闭窗口不等于停止后端任务，重开读取现有 snapshot。

## 实施阶段

| 阶段 | 交付物 | 主要改动位置 | 完成条件 |
| --- | --- | --- | --- |
| P0：解释清楚状态 | 修复详情传递、结构化展示状态、中文原因与动作、菜单直达问题 | `GatewayStatusSupport.swift`、`ProviderSupport.swift`、`ProviderSettingsPresentationSupport.swift`、`ServiceMenuViews.swift`、`MenuBarApp.swift` | 无 Provider 降级主文案；每个问题有影响范围和处理入口 |
| P1：统一窗口和操作 | 一个窗口/服务商选择/已保存快照；模型主区；连接折叠区；草稿保护；分阶段应用；明确测速范围 | `ProviderSettingsWindow.swift`、`ProviderSettingsView.swift`、`ModelBenchmarkWindow.swift`、`SettingsActions.swift`、`ProviderWindowLayoutSupport.swift`、本地化资源 | 接入、调整模型、测速、修复异常全程不离开同一窗口；失败保留正确提交状态 |
| P2：先测后加入 | 可测试未加入的缓存模型；选择与测速彻底解耦；评估刷新仅发现策略 | `src/catalog/service.rs`、benchmark target 解析、macOS 测速参数和结果展示 | 测试不写 selected_models、不改客户端目录、不重启；未授权/未知目标明确失败 |

P0 优先复用现有 `status --json` 和 `providers list --json`。不要继续解析可翻译的展示字符串，也不要用 `title.contains("降级")` 决定颜色、动画和动作。枚举只覆盖实际状态，不建立通用健康平台。

P1 以现有 ProviderSettings 窗口为承载，复用模型表格和 benchmark 数据逻辑。提取一个窗口级 ObservableObject 保存共有快照、选中 ID、各服务商草稿和操作状态；表单与测速继续保持各自的局部职责，不把所有逻辑塞入一个大类。旧 selectors 直接打开同一 controller 并定位对应区域，删除旧独立窗口生命周期。

应用状态使用最小状态机：`idle → validating → saving → restarting → syncing → completed/failed(stage)`。所有会重启网关的操作与 benchmark 生命周期协调，普通阅读与筛选不应被全局 isBusy 锁住。

P2 不只是把请求中的 models 数组接到 UI。当前 resolver 拒绝未加入模型，需要显式的待测目标解析路径：仅允许已配置且可用的服务商及其已发现/已验证的手动模型，复用现有认证与协议转换，不扩大到任意 URL 或任意凭据。保留原有 benchmark 请求的既定含义。

本期不新增依赖、不迁移密钥存储、不扩展到跨服务商自动容灾，也不重写 gateway 转发热路径。

## 验收与消融

先用同样的任务比较现有双窗口、仅改文案、完整统一流程。邀请约 5 名不熟悉 Provider 概念的使用者，记录完成时间、误操作、求助次数和切换窗口次数，不新增线上埋点。目标不是已测结论：至少 4/5 人能独立完成下列任务，并在 10 秒内说出异常原因和下一步。

1. 新增一个服务商，调整为两个模型，应用后说明何时能在 Codex 看到它们。
2. 一家服务商刷新失败、另一家正常时，识别影响范围并找到重试入口。
3. 当前服务商未加入模型时，从提示直接选中并应用。
4. 改动连接字段后切换服务商，再返回，草稿仍在且不会被测速或刷新覆盖。
5. 找到一个已加入模型的响应速度，区分未测、旧结果、超时与本次成功。

行为回归覆盖：官方只读连接与模型选择、AWS、Baidu bridge、辅助模型、手动上下文、禁用服务商、全选/全不选、未知状态、已提交后失败、Fusion 引用校验、外部修改冲突、测速中重启互斥，以及不同服务商同名模型不串结果。

修复异常详情格式问题时，先复现真实 CLI JSON 到 Swift 解码的契约，观察失败后修复；不能只喂给测试自行编造的 `provider-issue:` 字符串。针对用户可见行为断言，不用截图文本或固定列数代替交互测试。
