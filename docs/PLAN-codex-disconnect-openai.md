# PLAN：Codex 断开时重置 OpenAI 配置

状态：已实施（分支 codex/perf-disconnect-openai）。原评审版本：2026-11-04；核对工作区 HEAD：`d925b0a`。

## 目标与已确认决策

- 断开不再查找、解析或恢复旧 TOML 备份，直接生成官方最小配置。
- 目标文件完整内容为 `model_provider = "openai"` 加末尾换行。不写自定义 `[model_providers.openai]`、模型名、网关地址、Mixin 标记或模型目录路径；模型选择使用客户端默认行为，实施时实机验证。
- 当前 Codex home 下全部历史统一到 `openai`，包含其他 Provider、普通会话和归档会话；不依据安装记录限定范围。
- 历史归一化失败不阻断断开、不回滚配置、不让 GUI 把已断开显示成失败。明确显示未完成项，支持重复断开重试。
- 配置写入本身失败仍应报错，不能把尚未断开显示为成功。
- 本次聚焦断开；不重构整个接入流程，不增加后台任务框架、新依赖或自定义抽象层。

## 当前行为（源码事实）

- `src/cli/codex/install.rs` 的接入流程读取旧 TOML、解析后 upsert，再交给 restore 保存；当前工作区并非完全从空文档生成。
- `src/cli/codex/restore.rs` 的断开依赖 restore record 或 legacy backup，还会检查配置和 catalog 是否漂移。没有原备份可能直接拒绝断开；备份仍为 Mixin 配置可能导致恢复后依旧 managed。
- restore record 不登记历史会话，断开没有调用历史迁移；`src/application/agents.rs` 的提示却承诺迁移。
- `src/cli/codex/history.rs` 已覆盖 sessions、archived_sessions、state_5.sqlite/threads 和 sqlite/codex-dev.db/local_thread_catalog，但逐项使用 `?`，单个错误会提前结束。缺失或非法 provider 被跳过；SQLite 直接复制主文件作备份，需考虑 WAL。
- `src/cli/codex/switch.rs` 和 agents 共用卸载路径，并通过恢复记录与配置判断状态；只改 TOML 而保留旧记录可能仍报告 drift/error。

## 目标流程

1. 沿用实际配置路径解析和现有锁，确定对应 Codex home。不存在的配置允许创建；不要求原文件可解析。
2. 使用现有 platform 原子写入及权限 API 写入最小 TOML，读回确认 provider 为 openai 且无 Mixin 端点/标记。失败报告真实错误。
3. 认证不读取历史备份：保留可识别的真实认证，移除可识别的 Mixin 假认证；没有真实认证则提示重新登录。无法识别或无法清理时保留文件并明确报告“配置已重置，认证需处理”，不假称原生登录可用。
4. 退休本配置对应的旧恢复记录、owner 和 switch 状态，使其不再驱动恢复或让原生配置误判为 drift。保留 official switch 所需的“上次接入模式”语义。旧 transaction 不可在下次操作把配置恢复成 Mixin；实施需明确提交顺序，避免重置后的遗留 journal 回放。
5. 只清理可确认归属的 Mixin catalog、接入凭据及 skill 注入；不以损坏 TOML/restore 内容推导任意删除路径。未知遗留文件不影响原生配置生效，显示清理警告。旧备份可以留作救援资料，但不参与正常断开算法。
6. 主配置重置后，对全部历史执行尽力归一化：逐文件继续处理、数据库独立处理。修改仅限 provider 字段，保留会话内容、ID 和其他元数据。缺失/null provider 根据客户端语义处理，不能无声当作验证通过；损坏数据记录为未处理。
7. 历史修改前保留数据救援副本（与“恢复旧配置备份”是不同职责）。备份失败则跳过该项并警告；SQLite 使用原生一致性备份/事务能力，不能只复制可能有 WAL 的主文件。复用现有依赖与 API。
8. 输出主操作结果和历史汇总：已断开、变更数量、失败/未处理数量及重试方式。历史错误不进入整个 disconnect 的失败分支；不要声称“全部历史已完成”。重复断开仍执行历史修复，已为 openai 的项不重复改写/备份。

## 结果与失败语义

| 情况 | 结果 |
| --- | --- |
| 备份不存在、损坏、仍指向 Mixin | 不读取，不影响写入官方配置。 |
| 当前 TOML 不存在或损坏 | 直接生成最小 TOML；写入失败才报告配置重置失败。 |
| 某个 rollout 损坏、不可写，或数据库锁定 | 配置保持 openai，处理其他项，返回已断开并附历史警告。 |
| 归一化成功 | 报告实际修改数量；不据此保证旧模型在 OpenAI 上一定可用。 |
| 没有真实登录 | 已重置，提示在 Codex 登录。 |
| 旧恢复状态清理失败 | 保留已提交配置并报告清理未完成；状态检查不能仅因旧记录把官方配置判成 managed。 |

## 风险与约束

- 完整覆盖会移除 TOML 中的 MCP、偏好和其他自定义设置：这是本次选定语义，界面明确说明，不做合并。
- Codex 正在运行可能回写历史；本次不强杀客户端。提示重启，历史可重跑，不承诺跨 JSONL/SQLite 的全局原子性。
- 单条历史错误不阻断流程；扫描还需有界等待与进度，特别是 SQLite busy timeout，避免 GUI 长时间无响应。不引入无限重试或脱离生命周期的后台进程。
- 固定数据库路径是当前实现覆盖范围，不能宣传支持所有未来 schema；未知 schema 报未处理，不猜测写入。
- 只归一化 provider，不擅自改历史模型 ID；跨厂商模型不可用属于后续选模，不扩大本次修改。
- 最小 TOML 的客户端默认模型、登录表现须实机确认；本计划不声称已经验证。
