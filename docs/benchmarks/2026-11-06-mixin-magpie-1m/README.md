# Mixin vs Magpie：40 路百万 token 图像会话

2026-11-06，本机三轮隔离回放中，Mixin 的采样峰值 RSS 中位数为 **305.0 MiB**，Magpie 为 **566.6 MiB**，降低 **46.2%**。两者整轮 CPU 耗时接近；持续流式阶段 Mixin 的 CPU 更低。

适合这组数据的产品表述：**小而美，轻量强悍的本地 AI 网关。** 数字说明可写为：**40 路百万上下文含图请求，本机对照中采样峰值内存约减半。**

## 结果

以下均为三轮结果的中位数。MiB 按 1,048,576 字节计算，CPU 100% 表示占满一个逻辑核心。

| 指标 | Mixin | Magpie | 对比 |
| --- | ---: | ---: | --- |
| 装载及流式期间采样峰值 RSS | 305.0 MiB | 566.6 MiB | Mixin 低 46.2% |
| 40 路持续流式时 RSS | 254.3 MiB | 450.3 MiB | Mixin 低 43.5% |
| 40 路持续流式时 macOS 物理足迹 | 36.7 MiB | 467.2 MiB | Mixin 低 92.1% |
| 装载阶段 CPU 累计耗时 | 7.03 秒 | 6.92 秒 | 接近，Mixin 高 1.6% |
| 持续流式阶段 CPU | 1.15% | 2.90% | Mixin 低 60.3% |
| 整轮 CPU 累计耗时 | 7.31 秒 | 7.63 秒 | 接近，Mixin 低 4.2% |

RSS 与物理足迹来自不同的 macOS 计量口径，表中分别列出。宣传中的“峰值内存约减半”采用采样峰值 RSS。

| 轮次 | Mixin 峰值 RSS | Magpie 峰值 RSS | Mixin 整轮 CPU | Magpie 整轮 CPU |
| --- | ---: | ---: | ---: | ---: |
| 1 | 305.0 MiB | 576.5 MiB | 7.31 秒 | 7.63 秒 |
| 2 | 327.9 MiB | 514.8 MiB | 7.24 秒 | 7.61 秒 |
| 3 | 302.6 MiB | 566.6 MiB | 8.12 秒 | 7.92 秒 |

## 场景与校验

- 两个网关同时承载相同负载：8 个主会话，每个主会话对应 4 个子会话，共 **40 路并行请求/网关**。会话关系由脚本回放。
- 每一路都携带完整的 **1,000,000 文本 token** 历史及 **2 张 1024×768 PNG**，子会话同样携带完整历史。模型窗口设为 1,048,576 token。
- 文本为合成的代码审查、请求处理及验证记录，共 558 条消息；使用 `tiktoken 0.14.0 / o200k_base` 逐条编码，正文 token 数之和精确为 1,000,000。图像及协议封装开销另计。
- 上游逐请求验证完整历史哈希及两个 PNG 的字节哈希。对同名的 Mixin/Magpie 请求成对返回相同流内容，每 250 ms 追加 128 个 ASCII 字符。
- 每轮先启动 8 路主请求，主请求输出首段文本后再启动 32 路子请求。确认双方都达到 40 路活动请求后，持续采集 20 秒 CPU，随后在相同活动负载下采集物理足迹，再统一结束流。
- 每个网关三轮共 **120/120 请求成功**，240 张图像输入通过哈希校验，所有对应请求的最终输出哈希一致。
- Mixin 开启 context。每轮独立数据库均实际包含 40 个会话、22,320 条压缩正文及 40 条响应映射，`integrity_check` 均为 `ok`。

## 环境与采样

| 项目 | 配置 |
| --- | --- |
| 主机 | Apple M2，8 个逻辑核心，16 GiB 内存 |
| 系统 | macOS 27.2 |
| Mixin | `codex-mixin 0.7.7`，提交 `3e372ab90dad4de499643acf01172a753f435386` 的本地 App 内嵌 CLI |
| Magpie | 本地 `0.1.3051` |
| Mixin 启动方式 | `serve --no-client-sync`，context 开启 |
| Magpie 启动方式 | `web --addr <隔离页面地址> --no-open --gateway`，独立网关地址 |
| 请求协议 | OpenAI Responses HTTP SSE |

每轮使用全新的 HOME、配置、数据目录、端口、context 数据库和服务标识；三轮轮换两个网关的启动顺序。上游是独立 Node 进程，发压器也是独立进程。网关数字统计各自的进程树，本次每个网关均为单进程；GUI 外壳、发压器和假上游不计入网关数字。

CPU 使用 `ps` 的进程累计 CPU 时间差，包含用户态与系统态，装载阶段可使用多个核心。RSS 每 250 ms 采样，峰值取采样最大值。物理足迹使用 `vmmap -summary`，在 CPU 稳态窗口之后、40 路流仍活动时取三次快照的中位数。整轮 CPU 从装载前累计至全部响应完成、完成后空闲采样结束。

本次测量的是网关处理与转发开销；模型响应由受控上游生成。结果中的 `products.replay` 是整套压测父子进程树合计，包含网关和假上游，不作为独占发压器指标使用。
