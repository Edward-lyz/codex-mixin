# Provider 管理用例规范

继承上级规范。这里负责 provider 新增、修改、发现、模型管理及托管 skill 协调。

- `build.rs` 组装和校验输入，`discovery.rs` 处理端点发现，`models.rs` 处理模型变化，`skill.rs` 处理托管资源；沿用现有归属，不把全部流程塞进入口文件。
- 主配置先提交，再失效能力缓存、执行网络发现/探测与客户端同步；网络操作不得持有配置锁。
- 同步失败必须保留已提交事实和阶段，允许通过明确刷新入口重试；不得重复新增 provider。
- 官方模型与自定义模型保留明确来源、稳定标识和人工选择；发现不得覆盖用户手动设定。
- 托管 skill 依据管理标记识别，只备份/替换本项目拥有的内容；遇到用户修改报告冲突。嵌入脚本与模板也需要验证实际生成结果。
- 验证无效输入、提交失败、缓存失效失败、发现失败及用户配置保留，运行 provider 相关测试和 `cargo test --locked --test provider_commit_boundaries`。
