# CLI 核心接口规范

继承上级规范。CLI 是核心产品入口，负责 clap 参数、输入、输出、进度和退出码；可复用业务放入 application。

- 新增能力先保证 `--no-tui` 可运行，再接 UI。参数、帮助和返回结果应足以让无桌面环境的用户完成操作。
- 自动化入口使用已有 JSON contract。JSON stdout 只输出约定文档，进度/诊断进入 stderr；不得夹带 ANSI、提示语或日志。
- 保持 `interface.rs` 的协议版本、能力声明和路径描述准确；壳层通过它发现能力，不硬编码状态目录。
- `--json-errors` 保留 stderr 最后一行错误 envelope、非零退出码、`committed` 与 `stage`。未知提交状态使用 null，不冒充回滚。
- 参数边界解析 URL、路径和 `@env:NAME` 等密钥引用；不将密钥记录到命令日志。交互取消不触发写入。
- service 启动 server、客户端接入等是既有组合入口；不以此扩大普通命令对请求面或私有实现的依赖。core 不引用具体 TUI。
- 历史上留在 CLI 的业务在相关改动中向既有用例收敛，不新增机械 wrapper 或开展无关重构。
- 修改契约同时更新消费方与 `tests/` 中的 E2E；运行根级门禁，确认成功/失败 JSON、无终端路径和退出码。
