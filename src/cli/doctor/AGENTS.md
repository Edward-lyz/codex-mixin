# Doctor 诊断规范

继承上级规范。诊断、修复计划和结果呈现分开；默认诊断不写配置。

- 检查项明确返回 Ok、Warning 或 Error 及原因；无凭据、缺文件和超时不能伪装成健康。
- `repair.rs` 仅执行用户选定的修复路径，维持网关、配置、桌面操作的既有顺序；涉及桌面重启遵守现有显式 opt-in。
- 不从查询路径自动同步全部客户端，不因一个损坏客户端让无关诊断失效。
- 网关状态综合服务定义、PID、版本和健康检查，不以单个迹象判定可用。
- 日志诊断过滤认证及用户敏感内容；JSON 报告与人类输出使用同一检查结果。
- 验证仅报告时零写入、损坏配置、离线状态、部分修复失败和重启 opt-in，运行 doctor 相关测试与根级门禁。
